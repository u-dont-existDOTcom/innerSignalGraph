# Fixed semantic decisions — do not re-decide in Work

1. There are eight new graph tasks: seven optional practice entrances plus the explicit return-to-care task. They are not an eight-step sequence.
2. Keep the established best-friend, borrow-love, borrow-one-function and Protector tasks. Append only short optional bridges; do not rewrite their other behavior. Caring company deserves its own task because receiving support is not identical to generating affection. Wiser-self is not restricted to verbal advice, imagery or companionship.
3. Reuse existing `turn_task` (issue, phase, agreement, observation references, action, emotion) and its current private continuity. Do not invent a second therapist, goal engine, event scheduler or raw-draft store.
4. Add one derived case variable, `perspective_practice`. It is recomputed from the validated current-issue turn task and actual graph membership. Extractors emit `unknown`; arbitrary supplied enum values cannot select a practice. This makes the declared graph conditions executable while keeping intervention choice in the existing grounded task/path controller.
5. Ordinary supportive suggestions can offer a practice in a fitting situation. The user need not know a technical node name. A model must not infer acceptance from distress, praise, silence or a historical preference. A supported offer is not unconsented performance.
6. All eight tasks have tier 4. Existing accepted-task routing may prioritize them only within its current safety/external/relationship/trajectory limits. No new blanket deferral, priority inflation or high-risk claim is authorized.
7. When a chosen message is itself the outward action, keep `ROUTE.ACT_OUTWARD` primary and compose `IC.DRAFT_EDITOR` as explicit necessary support. Do not use a therapy gate to prohibit a sane boundary. Do not let the editor displace an uncompleted relationship assessment or urgent protection.
8. A graph edge records a relationship; it does not schedule a later turn. Represent pending return to care through the issue-bound task phase/marker/action/emotion already used by the system. Advance to `IC.DRAFT_RETURN_TO_CARE` only from the actual current request/attempt and retained consent. Do not equate sending a message with care completed.
9. The current adult can need support too. The raw draft is not automatically a child-state. Keep valid protest, actual wrongdoing, proportional responsibility, protection and non-cruelty together. Preserve attempted protective function versus actual helpfulness.
10. Common humanity is a standing relational stance. An explicit shared-suffering exercise is optional. Do not weaken any existing owner-approved common-humanity principle merely because its exercise is optional.
11. Keep the existing Nurturer/Protector/Guide roles; do not invent a fourth internal part called Editor. The editor is a useful stance that may borrow those functions, not an ontological assertion.
12. Use one short invitation and room for the response. If the five-second narrative phrase helps, do not demand a longer processing ritual to certify it.
13. Religious/philosophical/exemplar variants are optional reference material attached to these functions. They are not eight more task nodes, not added to every prompt, not proof of medical efficacy and not a reason to prefer one religion. No new claims are needed.
14. Close behavior: a user can decline or defer inward work, stop the conversation, or choose no outward reply. Preserve unfinished meaning without nagging or unauthorized future messages. A changed issue cannot inherit practice permission or old completion.
15. Do not promote old frozen guide ZIPs, edit generated views by hand, change models, run paid provider calls, mutate real private cases, merge production, deploy, or install.
