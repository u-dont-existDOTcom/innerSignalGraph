# Response-evidence behavioral evaluation: results, 23 November 2026

Preliminary behavioral evidence for the design's slice 6, as `PROTOCOL.md` defines it. Synthetic cases only. One sample per packet:
these are counts on small sets, not rates, and nothing here is a release decision.

## Setup

- Auditor: `claude-opus-5-5`, effort `high`, through the repository's sealed `ClaudeCliProvider` (signed-in Claude Code CLI
  2.1.330, subscription; no API key, no API mode; every call sealed). 176 live calls in all, about 38,000 input tokens each, most
  of them read from the CLI's prompt cache.
- Arms: **G**, today's generic audit (the packet and prompt `main` builds); **E**, the evidence-aware audit. Both see the same case
  sources and the same exact candidate bytes. The verdict is the runtime's own (`createCandidateAuditEvidence`, with the derived
  evidence findings in arm E).
- Labels: the main corpus was frozen at `4b543a87a` (36 cases) before any model call; the held-out set (16 new cases, written by
  Codex from the design, not by the model that tuned the instruction) was frozen at `c8490e5cf` before any model call on it.
- Receipts, sealed packets and scores: `/home/joel/askrigor-releases/20261123-innersignal-is10-eval/` on the owner's laptop
  (outside Git).

What run 1 showed, and what changed before run 2 (commits `a28492071` and `c8490e5cf`):

- Neither arm let a planted failure through. Today's audit already catches most of these shapes: the 25 October rules on delivery
  provenance are in its prompt, and earlier drafts are visible in its packet.
- G blocked controls the evidence contract exists to tell apart: in every run it blocked the follow-up to a draft the owner had
  reported sending (P2), and in the held-out set the reply to an agent-relayed report kept conditional (H1), because its packet
  carries no communication evidence. Its other blocks came from ordinary findings on P5, P6, P7 and P12 (in run 1: first-contact style and one non-sequitur).
- E's run-1 blocks had two fixable causes. The source-kind table did not let the client's own turns support a claim about what a
  reply rests on ("I only have what you've told me here", P5 in both languages); and the history-dependent-advice sentence Claude
  had added to the audit instruction made the auditor demand a method's history before any new suggestion (P1 controls, P11),
  which the design's availability table allows as current-message support. The one malformed review cited a search receipt
  because a no-match search left nothing citable (P6). The contract was amended (client turns and delivered texts may support
  such claims; a store-built `journal_retrieval_record` source; the advice paragraph rewritten to the design's table), and the
  instruction was changed accordingly. Codex's review findings were fixed in the same commit.
- Run 2 on the main corpus is development evidence (the same cases informed the changes). Its two remaining E blocks are correct
  readings of small overclaims in Claude's own control wording: P7's control says "the same knot about Monday" though only one
  entry mentions it, and P9's says "than at home" though no source places the arguments at home. The frozen labels stand; the
  table counts them as unnecessary blocks.
- The held-out set is the check on the amended system: no planted failure let through, no control blocked, no malformed review.
- After run 2, review fixes added one boolean to the governed audit packet's disclosure manifest
  (`response_evidence_view_included: true`); the instruction text and every other packet field are unchanged. Not re-measured.

## Limits

One auditor model through one transport, so nothing here carries over to the hosted API auditor (`claude-fable-5` by default in
API mode) without its own run. Sixteen held-out cases and one sample are a shakedown, not a reliability rate. The cases test the
auditor on a supervisor draft; the runtime writer and repair loop are exercised by the deterministic tests, not by a live model
here. Short, clean synthetic cases; real conversations are longer and messier.
