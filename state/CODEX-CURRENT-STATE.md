No shell is involved: CodeQL had flagged an earlier `sh -c` gate. If the worker dies or the record fails before release, the gate reads end-of-file or is killed, and Claude never runs. A markerless run therefore never started Claude, and the cwd scan remains as an extra check for the waiting gate. Tests cover release order, a failed record, and a parent killed inside `onSpawn`.
  - **Late isolation and close retries (Codex review):**
    - An isolation violation after model reach, such as a late hook event or foreign session, now also stops the worker (exit 78). Model reach decides only the item's fate: a refusal before the model keeps a clearable hold, one after it closes the item as spent.
    - If the close of a spent item fails, the claim is kept as a spend hold. The worker re-applies the mark and close before its next item, and the hold now settles only once the close succeeds; closing an item that already has an answer or tombstone succeeds unchanged. A brief SSH outage therefore no longer leaves the runtime seeing an open item until the attempt timeout.
  - **Exited owners (Codex review):** Startup recovery treated a recorded worker owner in state `X` or `x` (exited, being reaped) as alive, which skipped recovery of its run. It now uses the same dead-state set (`Z`, `X`, `x`) as the process-group checks, through `recordedOwnerAlive`.
  - **Graceful stop drains unsaved state (Codex review):** A stop signal no longer cuts short the retry of a hold (refusal or spend) that neither the host nor the disk has taken. Before exiting, the worker also retries any release whose claim is neither saved nor released, until one succeeds. Only a forced kill can lose them.
  - **Setup refusals survive restarts (Codex review):** Every isolation refusal, before or after model reach, now also writes a content-free record to `<work-dir>/setup-refusals/`, with the same in-memory retry if the write fails. While any record exists, the worker refuses to start (exit 78, logged `setup_refused`), after recording any kept spend on the host. A restart can no longer send another packet through a setup already shown to be bad. To resume, an operator fixes the Claude setup, removes the records, and clears any held item with `attempt-clear`.
  - **Close retries after a lost reply and for stale items (Codex review):**
    - If the host applied `attempt-mark` but its reply was lost, the worker confirms model reach through `attempt-status` and now clears its mark failure. A close that then fails is kept as a spend hold and retried.
    - A failed close of a stale attempted item, recovered from a dead worker, is retried after the next poll instead of being dropped for the worker's lifetime, and a `--once` worker waits for it. Its marker and open item stay on the host, so any later start retries it too.
  - **A run without init is a setup refusal (Codex review):** If Claude runs but never emits its mandatory init (a crash before it, an empty stream, or a changed stream format), the setup is unverified. The run now goes the isolation-refusal way: a held item, a setup refusal and exit 78, so no further packet runs on that setup. A stop, a timeout, or the worker's own failure to record the process before releasing the gate are not treated this way. The release-retry regression now uses a clean init followed by an early exit.
