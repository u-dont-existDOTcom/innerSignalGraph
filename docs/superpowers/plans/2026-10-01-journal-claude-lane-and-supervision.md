## Rules

As in the Codex lane plan: no journal text, packets or answers in Git, logs or PR text; synthetic tests with sentinels; unchanged job IDs and operation keys for existing work; the listed gates pass; a state entry and a `docs/INDEX.md` line with its SHA-256 binding.

## 1. The Claude lane — implemented for hardest work

Generalize the worker to `--agent codex|claude` (keep `journal:work:codex` as the Codex default).

- **Where it runs.** The Claude worker is Linux-only and refuses other platforms with `JOURNAL_CLAUDE_LINUX_REQUIRED` before any host/provider action. macOS ignores XDG for its `~/Library/Caches` location and lacks `flock`, so it does not satisfy this worker's isolation contract. Claude Code is signed in on the owner's Linux computer; the exchange is on the import host. With `--remote <ssh host> --remote-checkout <path> --remote-config <path> --remote-node <path>`, every exchange action runs on the host over SSH (`-o BatchMode=yes -o ClearAllForwardings=yes`):
  - the dispatch listing;
  - the stdio work server, as the MCP server's command (`ssh ... node <checkout>/src/cli/journal-work-mcp.mjs ... --stage-dir <host dir>`);
  - promotion, through a new content-free subcommand on the host: `npm run journal:work -- promote --work-id <id> --stage-dir <dir> --execution-json <json> --subject <name>`.
  The secret never leaves the host.
- **The run.** In a new empty temporary directory, without a shell, environment limited to `PATH`, `HOME`, `LANG` and `XDG_CACHE_HOME=<per-item run dir>/cache`. SSH host actions still receive only PATH, HOME and LANG. The CLI invocation is:

  ```text
  claude -p "<instruction>" --model <record.model> --effort <record.effort> --output-format stream-json --verbose
    --setting-sources "" --settings '{"disableAllHooks":true}' --disable-slash-commands --include-hook-events
    --mcp-config <0600 file> --strict-mcp-config --tools ""
    --allowedTools mcp__journal__get_journal_work_packet mcp__journal__submit_journal_work_result
    --permission-mode dontAsk --no-session-persistence
  ```

  Dispatch labels for this lane: model `claude-opus-5-5`, effort `max`. The Claude Code model argument is `opus`; map the label explicitly and refuse any other.
- **Full packet and memory bounds.** Both stdio tools declare `_meta: {"anthropic/maxResultSizeChars": 500000}`. The complete hardest fetch value, including instructions, schema and envelope, is limited to **450,000 characters**. Producers conservatively include the maximum work-ID/provenance width; the controller checks materialized dependencies before charging a hardest slot or invoking the port, and the exchange checks before publishing. The host's `packet-check` returns only `allowed` and the exact `packet_length`; the tool independently checks the same cap. Before promotion the stream reader matches `get_journal_work_packet` tool-use IDs to the model-visible `tool_result` text and keeps only its length. A mismatch or missing result refuses admission as `rejected:PACKET_TRUNCATED`; oversized preflight uses `rejected:PACKET_TOO_LARGE` without starting Claude. The line cap is `3 * 4 * 450000 + 1048576` bytes (about 6 MiB): three copies, JSON/UTF-8 expansion and headroom, with four such lines' worth per stream. Newline scanning examines only each new chunk and joins each finished line once. A synthetic five-megabyte line benchmark uses a generous five-second bound so loaded CI does not fail a linear reader. Codex retains its 1 MiB line/16 MiB stream bounds.
- **Role bounds.** Hardest work can reach extractor, omission_checker, reference_reader, fidelity_auditor, reconciler, pattern_builder and pattern_reviewer; cold_consumer is also supported by the exchange, although the runtime does not currently escalate it. visual_reader remains unavailable on this route. Extraction/reconciliation use existing 180,000-byte input bounds and split supported batches; a too-large final reference/fidelity or single-unit extraction is unresolved with `JOURNAL_WORK_PACKET_TOO_LARGE`. Dependency outputs are checked after materialization. Pattern source/build groups split by complete request size, then pattern-review candidate groups fit both their configured byte budget (formerly up to 3 MiB) and the hardest envelope. A single candidate/source/build packet that cannot split is recorded as unresolved without calling Claude.
- **Isolation and model reach.** Content-free system events may precede init; init is mandatory before assistant or user events. Bad/duplicate init, extra server/tool, nonzero skills/slash commands or a hook event immediately kills the process group and retains `isolation_refused`. A refusal before model reach (normally at init, for example after a Claude Code update or a settings change) does not close the item: it stays open behind a clearable hold, and the worker stops with content-free exit status **78** (setup refused). A later worker that finds such a hold stops at once without closing it or trying further items, and also exits 78. After fixing the setup, the operator clears the hold with `attempt-clear` within the item's TTL; a resend after the TTL is refused and the unit is recorded as a failed hardest attempt. A refusal after model reach closes the item as spent. Model reach requires positive input or output token usage attributed to a non-synthetic model, or a real tool-use event. Init, user text, zero-usage error results, cost fields and assistant events whose model is `<synthetic>` do not count. The host attempt is marked at the first such stream evidence while stdout is paused, before processing further events or waiting for Claude to exit. The sanitized CLI version and model-reach boolean are logged.
- **Persistence and admission.** Startup refuses `JOURNAL_CLAUDE_RUN_PATH_TOO_LONG` if the canonical work dir plus `inner-signal-claude-XXXXXX/run-XXXXXX` would exceed the 200-character slug boundary. XDG puts MCP logs inside that per-item run directory. After child/group termination, a finally block checks exact and truncated-plus-hash project and fallback cache directories. Any file or cleanup error refuses admission before promotion; those directories, run-local session/cache files and host stage directories are removed in finally, including after a killed run. Startup removes leftover project/cache folders only if the corresponding run directory no longer exists, preserving a live sibling's evidence. Exit 0, exact isolation init, no hook events, `is_error: false`, `subtype: success`, new session ID, positive expected-model output with no other output-producing model, complete packet text, fetch before first submit and host fetch/stage markers are required. Logs retain only content-free metadata. Tool schema errors expose fixed codes, anonymized property tokens, indices and counts.
- **Attempt markers and operator recovery.** The host reserves atomically with a synced temporary file and exclusive link; status changes use synced temporary files and atomic rename. Every exchange dispatch carries a content-free `attempt_identity`: the 48-hex digest of the base operation key, stripping reference-audit `:resend:N` and controller `:unsent-retry:<epoch>:<attempt>` / `:reserialize[:N]` suffixes. Both those new-digest work IDs and the exchange's `journal-work:<48 hex>:rN` successors share that identity. Host markers use only this dispatch identity; a hardest dispatch without one is refused with `JOURNAL_WORK_ATTEMPT_IDENTITY_REQUIRED`, with no exact-work-ID fallback. The marker filename retains the earlier base-work-ID encoding, and existing base-digest markers without an identity field remain held. Unparseable markers count as attempted. Real model reach marks attempted immediately; no-model failures release the reservation. Isolation refusal remains held; operator clearing is allowed only before packet fetch and model reach. Release first renames the marker to a private temporary name, verifies its claim and reserved status, then unlinks only that name; a concurrent attempted mark survives. `already_attempted` and `isolation_refused` do not consume `--max-items`.
  Operator command: `npm run journal:work -- attempt-clear --work-id <id>`. It refuses any marker with `packet_fetched: true` or `model_reached: true`, regardless of status. Otherwise it clears `isolation_refused`, or a `reserved` marker at least **twice its recorded run timeout plus ten minutes** old (70 minutes for an older marker without a timeout). Attempted, malformed and fresh reserved markers are refused. Marker commands sweep their own stale temporary files.
- **Evidence.** `execution: { profile_evidence: "claude_code_model_usage_reported", effective_model_profile: <the model key from modelUsage>, effective_effort: record.effort, request_context_id: "claude-session:" + session_id }`, subject `local:claude-hardest`. The exchange port accepts this evidence kind for the `hardest` tier on the Codex route. Supervisor admission is deferred.
- **Provider outages and usage limits.** Real HTTP 401/403/5xx/529 failures emit a synthetic assistant and a zero-usage error result. Without real model reach, these release the reservation and never mark attempted. 5xx/529 pause for five minutes; 401/403 stop the worker with content-free exit status **77** (sign-in required). HTTP 429, assistant `error: rate_limit` and limited/rejected `rate_limit_event` retain the reset/30-minute pause. Failed releases are retried before further work. If the run already reached a real model, its attempted marker is retained even if a later limit/outage occurs. `--once` exits with content-free status **75** when paused instead of waiting. Provider HTTP status is read from structured status fields only; structured `ECONNREFUSED`/`ENOTFOUND` errors use the same five-minute pause without consuming an attempt. Claude Code 2.1.287 reports a refused connection only as a synthetic assistant `error` label: `server_error` or `unknown` pause the same way, and `authentication_failed` stops for sign-in. A reservation whose packet was served and that is older than its run timeout plus ten minutes belongs to a dead worker; the next worker closes it as spent. Before scanning for persistence artifacts, at run end and in startup recovery, the worker kills the run's recorded process group and confirms it is gone, so a lingering helper can't write after the scan; a run whose group survives is refused. The run directory is removed before admission; if removal fails the result is refused and the worker stops with exit 74. A reservation owned by a live sibling is skipped until the worker next waits one poll, and is logged once; an unspent reservation older than twice its run timeout plus ten minutes is reclaimed automatically. A process group whose remaining members are all zombies counts as gone. An attempted marker younger than its run timeout plus ten minutes is treated as a sibling's run in progress and is closed only once stale; the worker never starts Claude after a stop has been requested. The host reserves each Claude session (a content-free hash) at promotion, so a session can back only one answer across worker processes and restarts. A process group that survives the kill wait leaves its run directory for startup recovery and stops the worker with exit 74. Persistence/isolation still refuse admission. Subscription usage retains `total_cost_usd` as a cost equivalent, not a charge.

The implemented worker is `npm run journal:work:claude -- --remote <ssh host> --remote-checkout <host checkout> --remote-config <host private config> --remote-node <host node> --work-dir <laptop private work dir>`. The host must provide the exchange-root and secret-file environment variables to its noninteractive SSH command. `--remote-node` is required in remote mode and must be absolute: it names the host's Node 24 executable, or a host wrapper that sets those two variables and then runs it. A bare `node` on a noninteractive SSH `PATH` can resolve to a different runtime (the import host's resolves to Node 20). The remote worker passes no exchange secret or secret-file path in its command arguments or laptop MCP configuration. The content-free host commands are `journal:work -- dispatch --json`, `packet-check`, `stage-create`, `stage-check`, `stage-sweep`, `promote`, `stage-remove`, `close-unanswered`, and the attempt-marker commands. `total_cost_usd` is recorded with `cost_kind: subscription_cost_equivalent_not_charged`.

### Fourth-round lifecycle and compatibility corrections (2026-10-02)

1. **Consumed identities and immediate exhaustion.** The host exchange port and `journal:work` share `src/journal-import/attempt-markers.mjs`. Before a new hardest item is published, the port checks the base attempt identity on the import host. An attempted or isolation-refused marker (also a fetched/reached reservation) returns `exhausted` with `JOURNAL_HARDEST_ATTEMPT_EXHAUSTED`; no successor is published. Both direct reference-audit and controller paths check this outcome before charging a daily slot. The durable port retains terminal exhaustion, and the runtime records the hardest failure so the unit stays unresolved and calibration stops. The worker calls content-free `close-unanswered --work-id <id>` after isolation refusal, an already-attempted hold, packet-check refusal, or any failed run after real model reach. The encrypted unanswered tombstone carries only `exhausted: true`; completion sees it immediately and does not walk to a successor or wait for TTL. Closing never overwrites an answer that won first. A sibling's live reserved marker is skipped without closing its item.
2. **Fetch/reach recovery.** The host work server atomically records `packet_fetched: true` on the same attempt identity before returning a hardest packet. Stream reach records `model_reached: true` while marking attempted. Host fetch and CLI updates share a crash-releasing flock and synced atomic rewrites, preserving both flags under concurrent updates and status changes. Clearing refuses either flag at every status, including a reserved marker older than 70 minutes and attempted-to-isolation transitions. Releasing also refuses fetched/reached reservations.
3. **Dispatch compatibility.** Dispatch includes `attempt_identity`, a 48-hex base-operation digest, for both tiers; hardest consumers still require it. `listDispatch` skips malformed/oversized/mismatched records and reports only an integer invalid-record count. One bad hardest record cannot stop standard Codex work. No Mission Control dispatch consumer is implemented in this repository; external readers must tolerate `attempt_identity` and ignore fields they do not consume. The exchange design now lists the field explicitly.
4. **Standard-tier pattern effect retained (owner-visible fallback).** Splitting only at escalation would require composing partial source-freeze/build outputs and their independently bound receipts into a new parent scope. This round uses the owner's permitted documentation fallback and retains the existing pre-splitting behavior. Enabling the hardest lane also caps **standard** source/build batches and review groups at the 450,000-character complete hardest envelope; review groups otherwise allow 3 MiB. This can increase standard calls, change batch/group scope IDs and packet digests, and prevent replay of earlier larger-group outputs. The comparison regression demonstrates a single standard review group with the lane off becoming multiple standard groups with the lane on, without any hardest call. This standard-tier effect is a retained tradeoff for the owner to see.

Startup records the worker and detached Claude group using Linux PID/start-time identities in the private run directory. A later startup kills a recorded group whose owner is gone before stale-run/persistence cleanup, while preserving live siblings and avoiding reused PIDs. If the worker died before writing that record, a later startup that finds the parent's lock free kills any process group with a live process working in the run directory and confirms it gone first. If the lock file is invalid, `/proc` can't be read, or a group survives, the run is kept and startup refuses with exit 74. Synthetic regressions include a worker killed with SIGKILL. Supervisor section 3 and the supervisor tier remain unimplemented.

## 3. `npm run journal:import -- supervise --config <cfg> [--sample <n>]`

Runs on the host after a pilot or a full run, against the run's current committed or candidate generation.

- **Sample.** At least 20 units or 5% of processed units, whichever is larger, capped at the processed units. Stratify by the unit's outcome (clean, repaired, needs review), by size, and by stage of origin (text, visual). Include the units the importer's own audit sampled, up to half the sample, so the two audits can be compared. Store the seed and the sample, and reuse them on rerun.
- **Work.** For each sampled unit, the same two audit roles the importer's own audit uses, built by the same shared request builders: the source-first `reference_reader`, then the `fidelity_auditor` on the unit's imported records. They go out as `supervisor`-tier items under their own job IDs.
- **Report** (private runtime; the summary shows only counts and unit IDs):
  - per unit: preserved, omitted, distorted and unassessed reference items, critical misses, qualifier errors;
  - for units both audits covered: agreement counts per outcome pair (for example `supervisor: omitted, importer: preserved`);
  - for each omitted or distorted finding, the first stage that could have caught it: extraction (no record at all), the omission check (it ran and passed), reconciliation (it changed the record), or the importer's own audit (it scored the item preserved);
  - totals, and the residual counts this adds to the run summary under `supervisor_review`.

## 4. Retiring routine review

Proposed defaults; the owner can change them.

- Every finding the importer's own audit missed becomes a process fix (packet content, role instruction, batch bound, or a new mechanical check) with a synthetic test, and the next sample measures it again.
- Routine supervision stops after two consecutive samples in which the supervisor finds no critical miss that the importer's own audit missed, and the two audits agree on at least 90% of omitted and distorted items.
- After that, supervise one import in ten, and every import whose own audit reports a critical miss or more than 5% of audited units needing repair.
