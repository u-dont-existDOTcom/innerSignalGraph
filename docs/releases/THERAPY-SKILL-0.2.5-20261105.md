# InnerSignal connector backend 0.2.5 (plugin unchanged from 0.2.4) — 5 November 2026

Scope, plugin: none. Every file under `plugins/inner-signal-therapy/` is byte-identical to the 0.2.4 release (stable `048a68fdb0c112e5ca876b0d3d3fc079fa8dbf5f`), including the manifest, which stays at version 0.2.4. The served therapy protocol therefore does not change: version 0.2.4, SHA256 `eba8d1c2b46322f0717c59053c9464443bb2658b5d415ffd319f3ebcd2004fb2`. No gate or test in the repository ties the manifest version to the newest release record: CI pins the manifest blob and checks its version against a fixed string, and the manifest version is part of the protocol that is hashed. Raising it would move the protocol hash for a release that changes no therapy text, so it is left alone and the CI pins are not touched. Between `main` at `cb2008ce6` (the 0.2.4 backend) and `f5dc411ca`, nothing under `skills/` or `plugins/` changed.

Scope, backend: the hosted private-case connector image is rebuilt from `main` at `f5dc411ca`, replacing the running backend `cb2008ce6`. The stable 0.2.4 plugin is layered onto the rebuilt image, as in 0.2.3 and 0.2.4, so the protocol served still comes from `stable`. The rebuild carries three merged and reviewed development changes: #219 (self-directed risk stays visible to the reply check across turns, the long-conversation stop is fixed, and unchecked fallbacks are replaced), #224 (the first self-directed risk statement, and the first turn at its highest level, stay visible to the reply check after a lowering), and #226 (the longitudinal-risk evaluation, sealed Claude CLI calls, and the safeguards write-up). It also contains the fixed fallback message code (an on/off setting, `INNER_SIGNAL_OWNER_FALLBACK`) and a shared on/off reader for the two switches. Dockerfile and dependency lockfile are unchanged; `package.json` gains one script line.

Draft path: the ChatGPT reply-draft path stays OFF (`INNER_SIGNAL_MCP_SUPERVISOR_DRAFTS` absent or off). Switching it on later is a separate step and not part of this release.

Owner fallback: OFF. `INNER_SIGNAL_OWNER_FALLBACK` is unset on the host, which the code reads as off. The hosted connector does not read this setting, so nothing changes for it in this release.

Not in this release: any therapy-rule, map or guide change; public-guide publication; switching on the draft path; switching on the owner fallback.

Stable predecessor: `048a68fdb0c112e5ca876b0d3d3fc079fa8dbf5f` (0.2.4); live protocol (0.2.4): `eba8d1c2b46322f0717c59053c9464443bb2658b5d415ffd319f3ebcd2004fb2`.

Release gates: stable package CI (`npm run verify`) and the pinned plugin blobs, unchanged; the exact stable commit and tree; the candidate protocol hash computed on the host by the running backend's canonical loader and matched by the live readback, which must equal the 0.2.4 hash; a backend rebuild that keeps the running image under a rollback tag (`rollback-before-0.2.5`) and leaves the 0.2.4 rollback tag alone; post-restart health, tools/list identical to the pre-restart baseline (with no reply-draft tool listed), live protocol readback, the draft path off, and the owner fallback unset or off. Preserve the previous image, private data and credentials for rollback. A stable merge is not proof of deployment.
